# tek_passport — программно-аналитический модуль расчётов для паспорта безопасности объектов ТЭК

## Описание

Репозиторий — учебная реализация части процедур оценки последствий локальных аварийных выбросов горючих веществ: от ввода исходных данных через вычислительное ядро до подстановки чисел в регламентированные текстовые шаблоны Word. В интерфейсе фиксируется набор сценариев ПОУО (см. `app/core/scenarios.py`); фактический запуск расчётов задаётся рецептами в `app/pipeline/recipes.py` и реестром типов доменных сценариев в `app/domain/registry.py`.

## Сценарии

Ниже — только коды из `SCENARIOS` в приложении.

### Реализованные

Сценарии, для которых `get_recipe()` возвращает непустой список `ScenarioConfig` и runner выполняет расчёт (при корректно заполненных входных данных):

| ПОУО | Что моделирует | Тип | Основные эффекты |
|------|----------------|-----|------------------|
| **POUO1** | Резервуарный парк (ёмкость, пролив) | outdoor | Зависит от топлива: **diesel** — испарение, **воздушная ТВС** (ΔP, I, зоны пробита), огненный шар от облака, **пожар пролива**, оценка числа людей в зонах; **LPG** — вскипание, **струйный факел**, **огненный шар BLEVE**, люди в зонах |
| **POUO2** | Наружные трубопроводы природного газа (узел/магистраль) | outdoor | **Взрыв паровоздушного облака (ТВС)**, **факельное горение** по расчётному расходу, **огненный шар** |
| **POUO3** | Внутренние трубопроводы природного газа в помещении | indoor | **Взрыв в объёме помещения** (расход, масса, избыточное давление), **огненный шар** по массе облака, участвующей во взрыве |
| **POUO4** | Внутренний трубопровод **СУГ** в помещении | indoor | **Взрыв в объёме помещения** (СУГ), **огненный шар** (в цепочке используется полная масса выброса Mg, как в рецепте) |
| **POUO6** | Наружные трубопроводы СУГ (жидкая/паровая фаза, испарительная установка) | outdoor | **Взрыв ТВС** с учётом ветки `lpg_flash` (масса/энергия облака), **факельное горение**, **огненный шар** |

### Частично реализованные

- **POUO3** — блок отчёта про **факельное горение** не считается как полноценный `jet_fire`: выполняется сценарий-заглушка `jet_fire_stub` с фиксацией причины по методике шаблона (`app/domain/indoor_natgas.py`).
- **POUO4 (СУГ)** — то же для **факела**: `lpg_jet_fire_stub` (`app/domain/indoor_lpg.py`), без таблицы зон как у наружного `jet_fire`.

### В разработке

Выбор есть в Tkinter-комбобоксе (`SCENARIOS.keys()` в `MainWindowTk`), но для кода ниже **`get_recipe` возвращает пустой список**, расчёт не запускается:

- **POUO5** — «водонагревательные котлы в помещении» (`app/core/scenarios.py`): рецепт в `recipes.py` не заведён.
- **POUO4 + топливо «дизель»** — для комбинации разрешены `allowed_fuels` в описании ПОУО4, но ветка расчёта есть только для **LPG и indoor**; для дизеля список сценариев пустой.

## Архитектура

Разбивка по слоям (пути от корня репозитория):

- **core** — `app/core/`: сущности `Project`, `POUO`, `PipeRow` (`models.py`), список сценариев для UI `SCENARIOS` (`scenarios.py`), топлива (`fuels.py`), фасад `engine.py` над pipeline, численные модули в `app/core/calcs/` (ТВС, помещение, резервуарный парк, огонь и т.д.).
- **domain** — `app/domain/`: контракт сценария (`base.py`), реализации (`tvs_explosion`, `jet_fire`, `fireball`, `tank_park`, `indoor_natgas`, `indoor_lpg`) и **`SCENARIO_REGISTRY`** в `registry.py` — сопоставление строки `scenario_type` классу сценария.
- **pipeline** — `app/pipeline/`: связки входов и порядка шагов `ScenarioConfig`; функция **`get_recipe(fuel_id, is_indoor, scenario_code)`** в `recipes.py`; исполнение в `runner.py` (`pouo_to_input`, `run_pouo`).
- **report** — `app/report/`: сбор контекста и Word (`word_builder.py`), графики при необходимости (`charts.py`); каталог шаблонов `app/report/templates/`.
- **ui** — `app/ui_tk/`: интерфейс на Tkinter (`main_window_tk.py`), служебный вывод (`debug_output.py`); точка входа приложения — `app/main.py`.

## Как запустить

Нужен **Python 3.9+**. Пример команд в PowerShell:

```powershell
cd путь\к\tek_passport
python -m venv venv
.\venv\Scripts\activate
pip install -r requirements.txt
python -m app.main
```

Откроется окно выбора ПОУО и ввода данных; после расчёта результаты оказываются в `POUO.results`; отчёт в Word можно сформировать из интерфейса, если сборка приложения успешно подключила модуль `app.report`.

## Генерация отчётов

Демонстрация **без GUI**: `run_report_demo.py` собирает пример проекта (**POUO2**), вызывает `compute_project`, записывает `out/Отчет_тестовый.docx`:

```powershell
python run_report_demo.py
```

Соответствие кода ПОУО имени файла шаблона задаётся в `word_builder.py` (словарь `WORD_TEMPLATE_BY_SCENARIO`).

## Текущее состояние проекта

- Полные связки расчётов без заглушек по факелу для типичных **наружных** сценариев газа (**POUO2**) и **POUO6**; для **POUO1** реализованы обе ветки (**diesel** и **LPG**).
- **POUO3** (природный газ в помещении) и **POUO4** (СУГ в помещении) считают **взрыв в объёме** и **огненный шар**; для **факела** — только заглушки.
- **POUO5** и сочетание **POUO4 + дизель** в коде только как пункт UI, без активного пайплайна.
- Часть зависимостей в `requirements.txt` указана расширяемо под Excel/PDF; в дипломной версии опора на локальный расчёт и DocxTpl.

Отдельно: в коде встречается задел под **POUO10** (`app/core/calcs/boiler/`), этого кода нет в `SCENARIOS` и в списке сценариев Tkinter.
